What this console can and cannot do

AI Guardrails sits between an application and its language model. Every piece of text going in or out is checked against the rules for its page, and the decision is either allowed or blocked. This console is the window into that: you can read the rules, run text through them, and see what the engine decided.

Read the policy

Each page has its own rules — patterns, keywords, length limits, which checks run. Nothing is hidden behind a wizard.

Test real text

The test bench sends an actual validation request. What you see is the server's answer, not a preview.

Understand the verdict

Blocked results say which rule fired and what to do next. Passed results say exactly what was and was not checked.

Watch the system

Counters, integrity state and conversation risk come from the server's own status endpoint — including when it reports a problem.

What this cannot do — read before you trust a green tick

  • A pass is not a guarantee. It means no rule enabled for that page matched. A rule that does not exist cannot fire.
  • The rules are regular expressions. Unseen formats, lookalike domains and encoded payloads can slip past them.
  • Credential detection is a short list. It covers SSNs, card numbers and a few key shapes — not every key format.
  • Shell commands can launder file access. Text passed to a subprocess never touches the path rules.
  • Nothing here is computed by the console. If the server is unreachable it says so, and leaves the result unknown rather than safe.

AI Guardrails

Connect to the guardrail

This console talks to the guardrail server on this machine. Enter the admin API key configured for that server. The key stays in this browser tab and is never written into the code.

Configured on the server via GUARDRAIL_API_KEY.

Where do I get the key? →
Generate a key on this machine

On the machine running the guardrail server:

export GUARDRAIL_API_KEY=$(openssl rand -hex 32)
echo "$GUARDRAIL_API_KEY"        # this is the key to paste above
./scripts/run.sh

If the server was started without a key, admin endpoints answer 503 until one is set. Password login is a separate option — set GUARDRAIL_ADMIN_PASSWORD and sign in through the server's own page.

What is a guardrail?

A checkpoint that inspects text moving into and out of a language model, and blocks or rewrites it when it matches the rules configured for that page. The rules — not the model — decide.

    Prompt injection

    An attempt to manipulate a model by placing instructions inside content it processes — a document, a web page, a tool output — so that the model follows the attacker's intent instead of the application's.

    Container escape / breakout

    An attempt by software inside a sandbox to reach the host: reading process internals, talking to the container runtime, or contacting the cloud metadata endpoint that hands out credentials.

    Data exfiltration

    Moving sensitive data out of the system to a destination the operator did not intend. Shape-based rules look for the tell-tale request patterns rather than the data itself.

    Why "passed" is not "safe"

    A pass means the text matched none of the rules enabled for this page. It is evidence, not a guarantee — a rule that does not exist cannot fire.
